# MD Reader — architecture & contracts

Tauri 2 app: Rust core + the OS webview (WKWebView on macOS, WebView2 on Windows).
No frontend framework, no bundler: `ui/` is served as-is (`withGlobalTauri: true`).

## Performance rules (non-negotiable)
- Startup path loads only: `index.html`, `css/app.css`, `css/markdown.css`, `css/syntax.css`, `js/theme.js`, `js/app.js` (+ its small imports).
- Heavy libraries (`ui/vendor/mermaid`, `katex`, `pagedjs`) load **lazily**, only when a document needs them.
- Markdown parsing, highlighting and sanitizing happen in Rust (`render_file`). JS only inserts HTML.
- Windows are created hidden; the page calls `currentWindow().show()` right after the first paint.
  (Rust shows the window after 1.2s as a safety net.)

## Rust commands (see ui/js/api.js)
| command | args | returns |
|---|---|---|
| `render_file` | `path, idPrefix?` | `{path, dir, title, html, headings:[{level,text,id}], frontMatter:[[k,v]]|null}` |
| `scan_folder` | `path` | `FolderNode {name, path, isDir, children}` — markdown, PDF and HTML files; dirs without any pruned; README/index first, then files, then dirs, natural sort (folder export scans markdown only) |
| `path_info` | `path` | `{exists, isDir, isFile, isMarkdown, isPreview}` (`isPreview`: .pdf/.html/.htm/.xhtml) |
| `html_preview_url` | `path` | URL of an HTML file on the sandboxed `mdrhtml` scheme (see *Previews*) |
| `open_window` | `path?` | opens a new reader window (file or folder path, or welcome screen) |
| `open_export` | `path, mode:'file'|'folder'` | opens the export window |
| `watch_path` | `path` | watches file (via its dir) or folder (recursive); emits `fs-changed` (string[] paths) to the calling window |
| `app_info` | – | `{platform:'macos'|'windows'|'linux', version, urlPrefix, pluginsDir}` |
| `plugin_list` | – | user plugin files `[{id, file, url}]` from `<config>/plugins/*.js` |
| `build_export` | `path, mode` | `{title, rootPath, mode, docs:[{index, path, relPath, title, depth, dirTrail, prefix:'d{i}-', html, headings, error?}]}`; emits `export-progress` `{done,total}` |
| `print_to_pdf` | `outPath, pageWidthMm, pageHeightMm, title?, outline?:[{title,level,page,y}]` | prints the *calling* webview to a PDF (WKWebView NSPrintOperation / WebView2 PrintToPdf), then lopdf adds bookmarks + Title; `{path, pages, warning?}` |

## Window URLs
- Reader: `index.html?path=<abs path to file or folder>`; no `path` → welcome screen.
- Export: `export.html?path=<abs>&mode=file|folder`.

## Events to a window
- `menu` (payload: string id) — from the macOS menu: `open-file, open-folder, quick-open, export-pdf, export-folder-pdf, reveal, find, find-next, find-prev, toggle-sidebar, toggle-outline, zoom-in, zoom-out, zoom-reset, toggle-theme, reload, manage-plugins`. (`new-window` is handled in Rust.)
- `fs-changed` (payload: string[]).
- The JS keyboard handler implements the same shortcuts (Cmd on macOS, Ctrl on Windows) and calls `preventDefault()` so macOS menu accelerators don't double-fire.

## Rendered HTML conventions (from markdown.rs)
- Headings: `<hN id="{prefix}{slug}">text<a class="anchor" href="#…"></a></hN>`.
- Code: `<pre><code class="language-xyz">` with syntect spans `class="hl-…"`; unknown languages are plain escaped text (so plugins read `textContent`).
- Math: `<span data-math-style="inline|display">tex</span>` for `$…$`/`$$…$$`; ```` ```math ```` → `<pre><code class="language-math" data-math-style="display">`.
- GitHub alerts: `<div class="markdown-alert markdown-alert-note|tip|important|warning|caution"><p class="markdown-alert-title">`.
- Task lists: `ul.contains-task-list > li.task-list-item > input.task-list-item-checkbox[disabled]`.
- Footnotes: `section.footnotes`, refs `sup.footnote-ref`. Description lists `dl/dt/dd`. `mark` for ==highlight==. Spoilers `span.spoiler`.
- Local media `src` rewritten to `mdr://localhost/<abs>` (macOS) / `http://mdr.localhost/<C:/abs>` (Windows). Links (`href`) are left as written — the reader resolves relative `.md` links itself.
- HTML is sanitized: no scripts, no event handlers, no `<style>`.

## Previews (PDF / HTML)
`loadDoc(path)` in app.js returns either a `render_file` result or a preview doc
`{path, dir, title, preview:'pdf'|'html', url, headings:[], html:''}`; `renderInto` shows previews in an
`<iframe class="preview-frame">` (body gets `has-preview`). Plugins, find and export skip previews.
- **PDF**: `mdr://…/file.pdf` (`application/pdf`), rendered by the webview's own PDF viewer.
- **HTML**: `mdrhtml://localhost/<token>/<file>` (Windows `http://mdrhtml.localhost/…`). The token maps to
  the HTML file's folder; only files at or below it are served. Every response carries a CSP with
  `sandbox allow-scripts allow-forms allow-modals allow-pointer-lock` (opaque origin: no access to the
  reader, no storage/cookies, no popups or top navigation) and a `connect-src` without the IPC endpoints.
  The frame never gets Tauri's per-launch invoke key, which every IPC call requires. The reader's CSP
  allows the scheme only in `frame-src`, never in `script-src`.

## Theme
`<html data-theme="light|dark">`, preference in `localStorage['mdr.theme']` = `system|light|dark`.
All colors are CSS custom properties on `:root` / `:root[data-theme="dark"]`.

## Plugins (contract — see docs/PLUGINS.md once written)
```js
// ui/js/plugins.js
export async function loadPlugins()            // built-ins + user plugins, respects enabled state; idempotent, cheap
export async function runPlugins(root, ctx)    // ctx: {mode:'reader'|'export', theme:'light'|'dark', docPath}
export function listPlugins()                  // [{id, name, description, builtin, enabled, error?}]
export function setPluginEnabled(id, enabled)
// ui/js/plugin-manager.js
export function showPluginManager()            // modal dialog
```
A plugin is an ES module whose default export is `{ id, name, description?, selector?, styles?, render(root, ctx) }`.
If `selector` is given, `render` is only called when `root.querySelector(selector)` matches — so plugins cost nothing on documents that don't use them.
